# Checks and first integration test

## Stock CPA smoke test

On a Linux Docker host, run `make stock-smoke` for an opt-in test with two real CPA v8.0.63 containers, pinned by image digest. Docker and OpenSSL are required; Docker may download the image. The test uses a private internal Docker network with no external route and no published ports. The host must be able to reach its Docker bridge addresses. If Docker’s default address pools are exhausted, set `CPA_RELAY_TEST_SUBNET` to an unused private IPv4 subnet for this disposable test.

Only synthetic credentials are used. It verifies plugin loading, authenticated HTTPS export, sanitization, automatic discovery of multiple logins sharing a workspace, dynamic add/remove/delete-all, isolated same-file refresh, unchanged file mtimes and safe malformed-file omission. The receiver plugin is enabled after stock CPA's initial directory scan to avoid racing initial model registration; this does not waive any readiness requirement. Sampled HTTP-200 readiness must have a nonempty per-account `/v0/management/auth-files/models` registration and matching `/v1/models` discovery; file/runtime visibility alone does not pass. It also changes an unrelated plugin through stock `PATCH /v8/management/config` with healthy and offline primaries: unchanged Relay settings must preserve file identities/mtimes and original cache generation, still expire at the original deadline, never revive expired/drained state, and recover only from newer live data after a real receiver process restart. It checks authenticated drain, actual stock disable/re-enable after drain, and an abrupt stock disable without drain that retains unacknowledged cleanup. Containers and their private network are removed afterward. The printed private temporary directory retains synthetic fixtures and logs for inspection. **Model registration/discovery is not upstream inference**, comprehensive scheduler/protocol certification, ingress enforcement or an exhaustive log audit.

## Automated checks

Run on Linux amd64 with Python 3, OpenSSL and a C compiler:

```sh
make check
```

The Makefile selects Go 1.26.10, baseline amd64 and cgo. CI runs the same command on Ubuntu 24.04, then checks formatting and dependency tidiness. A local CI definition is not evidence that a remote CI run has passed.

Coverage includes:

- Fixed-schema Codex access-token projection: no refresh token, ID token, nested metadata, SIWC or arbitrary source fields escape. Active malformed credentials fail closed; disabled unusable and valid expired entries may be omitted without blocking usable credentials.
- Dedicated bearer authentication, duplicate authorization headers, empty/disabled state and secret-free public/admin status.
- Automatic discovery: seven physical sources sharing one workspace remain distinct; one refresh/email change preserves its ID and does not change others. Dynamic add/remove/delete-all, duplicate physical paths/index aliases, unsafe paths, changed inventories and list/get failures are covered. Known other providers/runtime-only entries are not read. Caps fail closed, not truncated.
- Host Get index/name/path identity checks and private durable source-path inventory: a malformed file hidden by CPA's list cannot turn into deletion while it remains on disk. Physical absence is checked without reading credential contents; inaccessible parents/check errors retain prior authority. The stock smoke exercises the real omission case, leading-space basename identity, unchanged mtimes and refresh isolation.
- V1 config keys (including null/empty values), snapshots and durable state are rejected explicitly without adoption or mutation. V2 restart/cache/replay and same-workspace receiver reconciliation retain separate ownership.
- Duplicate/unknown/deep/oversized JSON, unsafe IDs, replay/future/stale timestamps, explicit expiry, conservative JWT expiry/account binding, wrong protocol/provider and malformed HTTP.
- Redirect refusal/no bearer forwarding, untrusted TLS rejection, cancellation and response bounds.
- Durable original cache age and watermark, restart requiring a newer live snapshot, failed fetch preserving fresh credentials, successful full-snapshot removal and expiry withdrawal.
- Ownership collision refusal, symlinks, private paths/cache, locks, partial writes, contamination and concurrent callback persistence changes.
- Synchronous runtime acknowledgements for additions/removals, failed runtime update keeping admission closed, physical deletion only after runtime disable acknowledgement, and unchanged credentials avoiding runtime churn.
- Delayed/missing/disappearing model publication, exact runtime/model identity joining, unavailable/error records, observation errors and expiring model leases. All active managed credentials need exact enabled identities and registrations; at least one must be raw active/available. Mixed pools retain healthy admission; all-error pools, including elapsed transient/rejected retry lookalikes, stay closed. Checks also cover synchronized/available counts, safe reasons, measured check times and historical sync/error timestamps. See [status semantics and optional real-manager reproduction](status.md).
- Effective-settings/secret equality (not YAML text), invalid/changed authority draining, unchanged global reload preserving workers and bounded offline availability, explicit drain/fault/quarantine preservation, deliberate resume requiring a newer live snapshot, reconfigure/cancel/join, failed cleanup retaining ownership/locks across repeated Stop and then succeeding, startup withdrawal retry without restart, terminated-worker poll rejection, runtime contamination rejecting lock-independent polls and suppressing queued/periodic fetches while containment retries continue, callback-in-progress shutdown, race detection, lock-independent status/readiness/interception and expired-deadline admission.
- `tests/abi_smoke.py` loads the **built shared object** with `ctypes`, supplies actual C ABI host callbacks, uses a temporary trusted HTTPS server and invokes real plugin RPC envelopes. It checks same-workspace discovery, background native-thread save/model callbacks, isolated refresh, unchanged no-write/offline reconfigure, preserved explicit drain and runtime quarantine, add/remove/delete-all, delayed model publication, sanitization, authentication, failure retention, replay and buffer ownership. Failed quiesce returns an error; reconfigure and drain must retry the retained cleanup obligation before a successful drain permits replacement. All credentials are generated fake JWTs; no provider call is made.

The ABI test is a **mock CPA host**, not the CPA server. Go unit tests are also not proof of real provider or full protocol support. The implementation was developed against the pinned released SDK and source contract. The opt-in stock smoke covers the specific real CPA watcher, model-registration and disable/drain cases above; a real Codex request, full scheduler/protocol coverage, proxy/ingress enforcement, target libc/CPU and installed host logging remain operator integration checks.

An optional parser fuzz pass is:

```sh
GOTOOLCHAIN=go1.26.10 go test ./internal/relay -run '^$' -fuzz FuzzSanitize -fuzztime=30s
```

## Exact isolated CPA integration plan

Use two disposable CPA **v8.0.63** instances, matching the intended CPU/libc and service UID. Do not use production instances or real tokens for leak/failure tests. Keep the primary/receiver ports bound to loopback or an isolated private test network. Save restricted rollback copies of both configurations and state first.

1. **Load and ABI:** build with `make check`, record compiler/libc, install `dist/cpa-relay.so`, and start each stock CPA process. Verify metadata version 0.3.0, role/settings fields, menu and protected routes are registered. Missing/invalid settings must leave the installed gate unready with a 503. Stop if loading fuses or crashes CPA.
2. **Logging prerequisite:** set exporter `observability.logs.request-log: false` and `server.commercial-mode: true`, then restart. Disable capture in every proxy/APM. Put distinct generated canaries in fake access/refresh/ID tokens and nested SIWC metadata. Exercise authorized success, unauthorized export, upstream failure and disconnected clients. Search all host/proxy/forwarded logs, traces and temporary captures for those canaries and the relay bearer using a local script that prints only pass/fail (never paste tokens into commands or reports). No token may appear. Verify settings contain only the environment variable name. Do not proceed if capture cannot be excluded.
3. **TLS/auth:** configure the direct primary HTTPS endpoint with a trusted certificate. Missing/wrong/duplicate bearer headers must not export. Bad hostname, untrusted certificate, plain HTTP, user-info/query/fragment URLs and redirects must not make the receiver ready; verify a redirect destination receives no request/header. Disable any gateway compression on the snapshot route, because compressed bodies are deliberately rejected.
4. **Discovery/projection:** create several synthetic Codex files sharing one workspace plus a different-provider file. All Codex logins must have distinct opaque `credential_id` values while retaining the same `account_id`; no physical filename/path or renewal metadata may appear on the wire/status. Add a source during operation: it must appear on the next sync. Refresh only one token/email in place: only its receiver record may change; repeated unchanged syncs must not rewrite credentials. Rename a source: require delete-and-add. Alias a path/index or break List/Get/identity metadata: reject the whole export, not a partial snapshot. Make an active credential malformed; require failure and no immediate deletion/expiry extension. Replace a previously discovered file with JSON CPA drops from its list: export must still fail while the file exists, including after exporter restart. A disabled Codex record may have unusable token fields; a valid expired token is omitted. Over 128 discovered Codex sources, 4096 host entries or the response limit must fail without truncation. Legacy config fields must be rejected, not interpreted as authorization to broaden.
5. **Host runtime/models vs disk:** a receiver save must synchronously register/enable its managed runtime entry, but this alone must not open readiness. For every HTTP-200 readiness sample, verify each active managed file maps to an exact enabled runtime ID/index, at least one is raw active/available, each has nonempty per-account `/v0/management/auth-files/models?name=...` registration, and a corresponding `/v1/models` entry. Delay model publication in the native mock: readiness/interception must stay 503, status must respond, and the one-second worker must recover without a new snapshot or rewrites. Remove registrations or fail/block their observation: gate must close; an observation lease must expire within three seconds without waiting for that callback. Change one token; keep admission closed through acknowledgement and model confirmation. Never print token values. Discovery does not prove provider inference or a linearizable scheduler transaction.
6. **Removal and write failures:** disable or physically delete one source and accept a newer snapshot; only its credential ID must be withdrawn even when workspace IDs match. Delete all sources in an accessible parent: a valid empty snapshot must disable/delete all owned records and remain unready. An omitted-but-present file or an inaccessible parent must fail export, not authorize removal. Confirm the receiver saves a sanitized disabled tombstone, runtime is disabled **before** physical unlink, and an unrelated manual file remains untouched. Make a test save/runtime operation fail (test harness or controlled auth-dir fault); readiness must never become true, including after partial writes. Restore permissions before cleanup. A corrupt/invalid/failed fetched snapshot must not remove a still-fresh accepted credential.
7. **Freshness/replay/restart:** use a short but valid test stale interval. Stop export responses and observe the exact original generation/expiry deadline: readiness and normal/stream requests must reject at that boundary; cleanup must disable/remove owned records. Retrying old snapshots must not extend it. Restart while the primary is blocked: even a formerly fresh cache must remain unready. Unblock the primary and require a strictly newer live snapshot. Restart the exporter and verify its generation still increases. While ready, use stock `PATCH /v8/management/config` to change only another disabled plugin's settings: require no Relay file rewrites/withdrawals. Repeat while the primary is offline: original generation/deadline must not change, and expiry must still close readiness and withdraw records. A further identical reload must not revive expired state. A real receiver process restart during the outage must stay closed even with fresh cached tokens. Test both JWT-earlier and explicit-expiry-earlier cases with generated tokens.
8. **Ownership/contamination:** pre-create a colliding computed filename that is not in the inventory; it must neither be adopted nor deleted. In an already owned test record, inject a fake `refresh_token` or SIWC field during a save; readiness must remain/turn unready and the field must never be adopted into a live relay snapshot. Test a concurrent persistence update and verify post-save/audit failure closes admission. Use an isolated instance: local admin writers are not an adversarial security boundary.
9. **Lifecycle/drain:** while HTTPS/retry work is slow and separately while a host save/model callback is pending, reconfigure/quiesce/drain. HTTP/retry waits must cancel, callbacks must finish before ownership/context release, and status/probes/interception must remain responsive. In the native mock fail one disabled save: quiesce must fail, reconfigure must retain the engine/locks, and drain retry must invoke the callback and retire inventory only after success. Fail the first startup cleanup, recover host saves, and require readiness from a newer live snapshot without restarting. Then on stock CPA deny ingress, require authenticated POST `/v0/management/cpa-relay/drain` to return HTTP 200 with `state: drained`, verify removed/disabled runtime/files and empty inventory, and only then disable/unload. Before disabling, apply an unrelated global settings reload while the primary is healthy: the explicit drain must remain closed with no managed files. Re-enable and require a newer live snapshot; unchanged reload alone is not resume. Also verify fault/quarantine survive identical reloads, and changed secret/endpoint/state/namespace or invalid settings still close the old session. A blocked native callback cannot be canceled by this API; keep ingress closed until it finishes.
10. **Ingress is the real failure boundary:** separately test **abrupt** stock disable with active credentials and no drain: readiness must disappear/non-200 and incomplete cleanup must not be mistaken for success (the stock smoke checks retained inventory/tombstones). Stock CPA closes callback availability before native shutdown; do not expect acknowledged withdrawal. Recovery can require a full process restart to release resident-library locks. Also explicitly fuse, unload and rename the plugin in the disposable receiver; stop CPA and make the readiness request time out. Check that ingress denies missing/non-200/error/timeout probes, does not keep serving on cached success, and that clients cannot reach the listener directly. Verify all intended client protocols separately, including normal/SSE chat and any Responses, WebSocket, realtime or other endpoints actually used. Established requests/streams are not revoked by a new readiness failure. Do not infer protocol coverage from one chat test.
11. **Optional real-provider check:** only after steps 1–10 pass, with explicit authorization, use one dedicated test Codex account on the primary and one ordinary plus one streaming model request through receiver ingress. Confirm no refresh/ID token reaches the receiver. Record only status/model/result counts, not credentials or payload captures. This step is intentionally **not** part of automated checks or claimed complete here.
12. **Rollback rehearsal:** deny ingress; require a successful authenticated drain **before** stock disable/unload or process shutdown; verify its runtime records are disabled, reserved files removed and ownership inventory retired. Restore the paired private state/config/plugin backup with original permissions, restart, and require a newer live snapshot before admitting traffic. Record exact paths/commands for the real deployment separately; none are installed or executed by this repository.

Keep the ingress denied if any required check fails. There is no automatic production deployment, plugin updater, credential refresh loop, new listener, or CPA fork in this repository.
