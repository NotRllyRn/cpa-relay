# Checks and first integration test

## Stock CPA smoke test

On a Linux Docker host, run `make stock-smoke` for an opt-in test with two real CPA v8.0.63 containers, pinned by image digest. Docker and OpenSSL are required; Docker may download the image. The test uses a private internal Docker network with no external route and no published ports. The host must be able to reach its Docker bridge addresses.

Only synthetic credentials are used. It verifies plugin loading, authenticated HTTPS export, sanitization, background saves, same-file replacement and removal. Sampled HTTP-200 readiness must have a nonempty per-account `/v0/management/auth-files/models` registration and matching `/v1/models` discovery; file/runtime visibility alone does not pass. It also checks authenticated drain, actual stock disable/re-enable after drain, and an abrupt stock disable without drain that retains unacknowledged cleanup. Containers and their private network are removed afterward. The printed private temporary directory retains synthetic fixtures and logs for inspection. **Model registration/discovery is not upstream inference**, comprehensive scheduler/protocol certification, ingress enforcement or an exhaustive log audit.

## Automated checks

Run on Linux amd64 with Python 3, OpenSSL and a C compiler:

```sh
make check
```

The Makefile selects Go 1.26.10, baseline amd64 and cgo. CI runs the same command on Ubuntu 24.04, then checks formatting and dependency tidiness. A local CI definition is not evidence that a remote CI run has passed.

Coverage includes:

- Fixed-schema projection: no refresh token, ID token, nested metadata or arbitrary source fields can escape. Valid unrelated identities are skipped before malformed token/optional fields; ambiguous/duplicate identities and selected malformed credentials fail closed.
- Dedicated bearer authentication, duplicate authorization headers, explicit account selection, empty/disabled state and secret-free public/admin status.
- Exporter-only `source_files`: one login selected from a shared workspace, missing/ambiguous sources and index aliases failing before reads, malformed/unreadable unselected sources ignored, basename/traversal/normalization validation, raw physical path verification (including a leading-space file aliased by stock CPA's trimmed `Name` while the intended file is absent), receiver setting rejection and source filename/path privacy. The stock smoke uses two physical logins with the same workspace ID, checks the selected login, missing-source failure without fallback/deletion, a real whitespace filename alias with trimmed host metadata, and disabled-source withdrawal.
- Duplicate/unknown/deep/oversized JSON, unsafe IDs, replay/future/stale timestamps, explicit expiry, conservative JWT expiry/account binding, wrong protocol/provider and malformed HTTP.
- Redirect refusal/no bearer forwarding, untrusted TLS rejection, cancellation and response bounds.
- Durable original cache age and watermark, restart requiring a newer live snapshot, failed fetch preserving fresh credentials, successful full-snapshot removal and expiry withdrawal.
- Ownership collision refusal, symlinks, private paths/cache, locks, partial writes, contamination and concurrent callback persistence changes.
- Synchronous runtime acknowledgements for additions/removals, failed runtime update keeping admission closed, physical deletion only after runtime disable acknowledgement, and unchanged credentials avoiding runtime churn.
- Delayed/missing/disappearing model publication, exact runtime/model identity joining, unavailable/error records, observation errors and expiring model leases. All active managed credentials need registrations, not just one.
- Reconfigure/cancel/join, failed cleanup retaining ownership/locks across repeated Stop and then succeeding, startup withdrawal retry without restart, terminated-worker poll rejection, runtime contamination rejecting lock-independent polls and suppressing queued/periodic fetches while containment retries continue, callback-in-progress shutdown, race detection, lock-independent status/readiness/interception and expired-deadline admission.
- `tests/abi_smoke.py` loads the **built shared object** with `ctypes`, supplies actual C ABI host callbacks, uses a temporary trusted HTTPS server and invokes real plugin RPC envelopes. It checks background native-thread save/model callbacks, delayed model publication, sanitization, authentication, failure retention, removal, replay and buffer ownership. Failed quiesce returns an error; reconfigure and drain must retry the retained cleanup obligation before a successful drain permits replacement. All credentials are generated fake JWTs; no provider call is made.

The ABI test is a **mock CPA host**, not the CPA server. Go unit tests are also not proof of real provider or full protocol support. The implementation was developed against the pinned released SDK and source contract. The opt-in stock smoke covers the specific real CPA watcher, model-registration and disable/drain cases above; a real Codex request, full scheduler/protocol coverage, proxy/ingress enforcement, target libc/CPU and installed host logging remain operator integration checks.

An optional parser fuzz pass is:

```sh
GOTOOLCHAIN=go1.26.10 go test ./internal/relay -run '^$' -fuzz FuzzSanitize -fuzztime=30s
```

## Exact isolated CPA integration plan

Use two disposable CPA **v8.0.63** instances, matching the intended CPU/libc and service UID. Do not use production instances or real tokens for leak/failure tests. Keep the primary/receiver ports bound to loopback or an isolated private test network. Save restricted rollback copies of both configurations and state first.

1. **Load and ABI:** build with `make check`, record compiler/libc, install `dist/cpa-relay.so`, and start each stock CPA process. Verify metadata version 0.1.0, role/settings fields, menu and protected routes are registered. Missing/invalid settings must leave the installed gate unready with a 503. Stop if loading fuses or crashes CPA.
2. **Logging prerequisite:** set exporter `observability.logs.request-log: false` and `server.commercial-mode: true`, then restart. Disable capture in every proxy/APM. Put distinct generated canaries in fake access/refresh/ID tokens and nested SIWC metadata. Exercise authorized success, unauthorized export, upstream failure and disconnected clients. Search all host/proxy/forwarded logs, traces and temporary captures for those canaries and the relay bearer using a local script that prints only pass/fail (never paste tokens into commands or reports). No token may appear. Verify settings contain only the environment variable name. Do not proceed if capture cannot be excluded.
3. **TLS/auth:** configure the direct primary HTTPS endpoint with a trusted certificate. Missing/wrong/duplicate bearer headers must not export. Bad hostname, untrusted certificate, plain HTTP, user-info/query/fragment URLs and redirects must not make the receiver ready; verify a redirect destination receives no request/header. Disable any gateway compression on the snapshot route, because compressed bodies are deliberately rejected.
4. **Selection/projection:** create two fake Codex auth files on the primary, selecting just one ID on both sides. Fetch locally with the dedicated secret supplied without shell history or output capture. Inspect only field names: fixed allowed keys, one selected ID, no refresh/ID token/last-refresh/SIWC/proxy metadata. Give the unselected source an invalid token/optional-field type with a valid unambiguous ID: selected export must still work. Give a selected source that malformed field, or duplicate/alias its identity, and require the whole export to fail. Duplicate the selected account in another file and confirm failure rather than arbitrary selection. Then configure exporter-only `source_files` with exactly one physical basename and confirm only that login is exported; the snapshot/public status must have no source filename. Selecting both same-workspace files must still fail. Rename/delete the required file: require export 503 without fallback, with no immediate receiver deletion while its accepted state remains fresh; restore the file to recover. Verify duplicate names/auth indexes fail, and unsafe path/glob selectors or any non-null receiver `source_files` field are rejected.
5. **Host runtime/models vs disk:** a receiver save must synchronously register/enable its managed runtime entry, but this alone must not open readiness. For every HTTP-200 readiness sample, verify each active managed file maps to an active enabled runtime ID/index, has nonempty per-account `/v0/management/auth-files/models?name=...` registration, and a corresponding `/v1/models` entry. Delay model publication in the native mock: readiness/interception must stay 503, status must respond, and the one-second worker must recover without a new snapshot or rewrites. Remove registrations or fail/block their observation: gate must close; an observation lease must expire within three seconds without waiting for that callback. Change the selected token; keep admission closed through acknowledgement and model confirmation. Never print token values. Discovery does not prove provider inference or a linearizable scheduler transaction.
6. **Removal and write failures:** disable a selected source and accept a newer snapshot (keep pinned source files present; deleting a required `source_files` entry's file must fail export instead). In account-only mode, deselection/removal can also produce an authoritative snapshot. Confirm the receiver saves a sanitized disabled tombstone, runtime is disabled **before** physical unlink, and an unrelated manual file remains untouched. Make a test save/runtime operation fail (test harness or controlled auth-dir fault); readiness must never become true, including after partial writes. Restore permissions before cleanup. A corrupt/invalid/failed fetched snapshot must not remove a still-fresh accepted credential.
7. **Freshness/replay/restart:** use a short but valid test stale interval. Stop export responses and observe the exact original generation/expiry deadline: readiness and normal/stream requests must reject at that boundary; cleanup must disable/remove owned records. Retrying old snapshots must not extend it. Restart while the primary is blocked: even a formerly fresh cache must remain unready. Unblock the primary and require a strictly newer live snapshot. Restart the exporter and verify its generation still increases. Test both JWT-earlier and explicit-expiry-earlier cases with generated tokens.
8. **Ownership/contamination:** pre-create a colliding computed filename that is not in the inventory; it must neither be adopted nor deleted. In an already owned test record, inject a fake `refresh_token` or SIWC field during a save; readiness must remain/turn unready and the field must never be adopted into a live relay snapshot. Test a concurrent persistence update and verify post-save/audit failure closes admission. Use an isolated instance: local admin writers are not an adversarial security boundary.
9. **Lifecycle/drain:** while HTTPS/retry work is slow and separately while a host save/model callback is pending, reconfigure/quiesce/drain. HTTP/retry waits must cancel, callbacks must finish before ownership/context release, and status/probes/interception must remain responsive. In the native mock fail one disabled save: quiesce must fail, reconfigure must retain the engine/locks, and drain retry must invoke the callback and retire inventory only after success. Fail the first startup cleanup, recover host saves, and require readiness from a newer live snapshot without restarting. Then on stock CPA deny ingress, require authenticated POST `/v0/management/cpa-relay/drain` to return HTTP 200 with `state: drained`, verify removed/disabled runtime/files and empty inventory, and only then disable/unload. Re-enable and require a newer live snapshot. A blocked native callback cannot be canceled by this API; keep ingress closed until it finishes.
10. **Ingress is the real failure boundary:** separately test **abrupt** stock disable with active credentials and no drain: readiness must disappear/non-200 and incomplete cleanup must not be mistaken for success (the stock smoke checks retained inventory/tombstones). Stock CPA closes callback availability before native shutdown; do not expect acknowledged withdrawal. Recovery can require a full process restart to release resident-library locks. Also explicitly fuse, unload and rename the plugin in the disposable receiver; stop CPA and make the readiness request time out. Check that ingress denies missing/non-200/error/timeout probes, does not keep serving on cached success, and that clients cannot reach the listener directly. Verify all intended client protocols separately, including normal/SSE chat and any Responses, WebSocket, realtime or other endpoints actually used. Established requests/streams are not revoked by a new readiness failure. Do not infer protocol coverage from one chat test.
11. **Optional real-provider check:** only after steps 1–10 pass, with explicit authorization, use one dedicated test Codex account on the primary and one ordinary plus one streaming model request through receiver ingress. Confirm no refresh/ID token reaches the receiver. Record only status/model/result counts, not credentials or payload captures. This step is intentionally **not** part of automated checks or claimed complete here.
12. **Rollback rehearsal:** deny ingress; require a successful authenticated drain **before** stock disable/unload or process shutdown; verify its runtime records are disabled, reserved files removed and ownership inventory retired. Restore the paired private state/config/plugin backup with original permissions, restart, and require a newer live snapshot before admitting traffic. Record exact paths/commands for the real deployment separately; none are installed or executed by this repository.

Keep the ingress denied if any required check fails. There is no automatic production deployment, plugin updater, credential refresh loop, new listener, or CPA fork in this repository.
